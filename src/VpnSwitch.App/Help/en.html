Quick start

D2C VPN Switch keeps several OpenVPN-based remote-access clients working side by side on one PC:

ClientServiceAdapter
device2cloud / machinetoserviceOpenVPNServiceInteractive (OpenVPN)OpenVPN TAP-Windows6
Sophos ConnectOpenVPNServiceInteractive (Sophos)Sophos-TAP
eWON eCatcher (Talk2M)Talk2mVpnServiceTalk2m-eCatcher
  1. The program starts after the Windows prompt (administrator rights) and searches automatically.
  2. The top line shows which client currently owns the shared service OpenVPNServiceInteractive.
  3. On the Switch tab select the client you want and click Activate selected.
  4. The log at the bottom shows what happened.
Disconnect existing VPN connections before switching.

Switch

Sophos Connect and OpenVPN/device2cloud both register the service OpenVPNServiceInteractive, but with a different openvpnserv.exe. Only one can be active. Activate selected (or double-click):

  1. stops the service,
  2. sets its ImagePath in the registry to the selected openvpnserv.exe,
  3. starts the service again.

eCatcher has its own service. For it, activate only starts the Talk2M service.

Repair eCatcher adapter

During installation eCatcher may take over another client's TAP adapter. device2cloud then cannot find its adapter (Adapter '{GUID}' not found). The repair assistant

  1. stops the Talk2M service,
  2. gives an adapter taken over by eCatcher back to OpenVPN (name OpenVPN TAP-Windows6),
  3. creates a separate adapter Talk2m-eCatcher for eCatcher (tapctl, otherwise addtap.bat),
  4. starts the Talk2M service again.
Close eCatcher first (also in the tray) and disconnect all VPN connections. Afterwards test device2cloud first, then eCatcher.

Services

Shows all VPN-related services. Red: start type “Auto” but the service is not running. Start, Stop, Restart act on the selected service. End running openvpn.exe ends stuck OpenVPN processes that block a TAP adapter; existing connections are dropped.

Network adapters

Shows TAP/Wintun and other VPN adapters with status and GUID. Rename, Enable and Disable act on the selected adapter. New TAP adapter creates another adapter with its own name so that every client has its own.

All “TAP-Windows Adapter V9” share the driver tap0901.sys. If a client installs an older driver (eCatcher: 9.0.0.21), adapters set up for the newer driver (9.24) may fail. Fix: repair the OpenVPN installation, align the driver in Device Manager, reboot.

Troubleshooting

Message / symptomCause and remedy
Adapter '{GUID}' not foundThe service OpenVPNServiceInteractive belongs to the wrong client. Activate the right client on the Switch tab.
CreateFile failed on tap-windows6 deviceDriver conflict (see Network adapters) or a stuck openvpn.exe. First End running openvpn.exe, otherwise repair the OpenVPN installation and reboot.
Adapter “Talk2m-eCatcher” missingRepair eCatcher adapter or New TAP adapter named Talk2m-eCatcher.
Error while switchingDisconnect VPN connections, check the Services tab and try again. The error text is in the log.
Program does not startThe Windows prompt (administrator rights) must be confirmed.
